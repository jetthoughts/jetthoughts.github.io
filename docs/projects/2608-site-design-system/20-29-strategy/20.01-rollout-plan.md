# 20.01 — Rescue Room rollout plan

**Date:** 2026-08-20
**Status:** Proposed
**Decisions:** [ADR-0003](../../../adr/0003-site-design-system.md) ·
[ADR-0004](../../../adr/0004-static-site-experimentation.md)

Every phase is one PR. Every phase names its gate before it starts, and the gate
is read before the next phase begins.

> **A/B testing was the original request and it is not available.** Per
> ADR-0004, real human traffic is ~9.7 sessions/day - 145 GSC clicks in 28 days
> plus Bing/DDG (GA4's ~300/day is 85-90% bots). The cheapest viable
> engagement test needs 192 days to reach power; lead conversion ~3.6 years.
> No phase below is A/B tested. Gates are **A** qualitative, **B** guardrails
> with declared rollback thresholds, **C** reversibility — all defined in
> ADR-0004.

---

## Sequencing principle

Phases are ordered by **whether layout moves**, not by size. That single property
decides the screenshot-baseline cost (143 macOS + 135 Linux) and how a
regression gets found:

- A **recolour** leaves every element in place. A fault is a wrong colour,
  caught in a screenshot diff, revertable alone.
- A **spatial** change shifts every page vertically. A fault is a layout break,
  and baselines churn wholesale.

Hence Phase 1 splits: 1a recolours, 1b moves things. This costs one extra
baseline re-record versus batching them, and buys a rollback point in between.
With no experiment available anywhere in this rollout, **reversibility is the
substitute for statistical confidence** — so the split earns its cost. It only
works because Phase 0 builds the re-record tooling first.

## Phase 0 — instrumentation and safety

**No visual change. No baseline churn. Blocks everything else.**

### 0.1 Conversion instrumentation (P0)

Today there is no way to measure any change to this site. 56 days of GA4
(property `328508492`) contain no form-submit event, no `generate_lead`, and
9 `click` events total. Worse than in the 2026-08-13 audit, which recorded
`keyEvents = 0`: `page_view` has since been marked a **key event**, so GA4 now
reports 4,063 "key events" that measure nothing. A non-zero conversion count
that counts page views will eventually be read as conversions.

This does not enable A/B testing — nothing does at this traffic (ADR-0004). It
is worth doing because absolute lead counts are readable even when rates are not
testable, because it removes a misleading number, and because the data has to
start accumulating before the revisit threshold is ever met.

- Fire `generate_lead` on audit / contact / free-consultation form submit.
- Un-mark `page_view` as a key event.
- Track CTA clicks with a `location` parameter (hero / section / footer /
  article-end), so "which CTA earns the click" becomes answerable.
- Add scroll-depth milestones on the homepage and the blog post template.

**Gate:** each event verified firing in GA4 DebugView on staging *and* once in
production, before Phase 1a starts. No sampling window needed — either it fires
or it does not.

**The key-event toggles are NOT "Paul's console-only work"** — this plan said
so twice and it was wrong (corrected 2026-08-20 after PR #495 marked
`contact_cta_click` through the browser). The read-only Data API cannot mark
key events, but the task never needed an API: **Admin → Data display → Events →
Create event → "Create with code"** takes an event name plus a Mark-as-key-event
toggle and needs no already-received data. Two dialog traps: it pre-selects a
$1 default key-event value (set it to "don't set", or every click books phantom
revenue), and the counting method stays "Once per event". Generalised rule:
exhaust the UI before declaring something blocked.

### 0.2 `bin/record-baselines <path>...`

Already a named automation candidate in `CLAUDE.md`; done by hand three times on
2026-08-14. `FORCE_SCREENSHOT_UPDATE=1 bin/dtest` rewrites all 135 Linux
baselines, so today accepting three of them means copying three out,
`git checkout -- test/fixtures/screenshots/linux`, and restoring. Every phase
below pays that tax without this.

**Gate:** re-record a known-changed baseline with the wrapper, confirm
`git status` shows only that file on both platform dirs.

### 0.3 Coverage check

Confirm a screenshot test exists for each of the five templates in scope
(`homepage`, `single-service`, `blog-list`, `blog-single`, `course-single`). Any
template without one gets a test **before** its phase, not after — a bundle with
no baseline is a bundle changed blind.

### 0.4 Establish the human-traffic baseline

Not to size an experiment — there isn't one — but so Gate B has a denominator
that isn't bots. Per `.okf/workflows/analytics-access.md`, that means GSC clicks
on the **prefix** property (or `page notContains elital`) plus Bing/DDG
sessions, and explicitly **not** GA4 `google / organic`. Record the 28 days
before Phase 1a starts, in this project, so every later before/after has
something honest to diff against.

**Exit:** events fire, wrapper works, coverage complete, human baseline
recorded.

## Phase 1a — style-only recolour

**One PR. Layout does not move.**

- New tokens defined and consumed: warm ink ramp, three light surfaces + one
  dark, ruby scale.
- `--color-primary` deleted — 161 `var()` references and 52 `#1a8cff` literals.
  Treated as a codemod, verified on **rendered output**, not source: the
  existing text-ratchet lesson (`marketing_copy_test` globbing source and
  missing three rendered defects on 2026-08-14) applies exactly here.
- Footer moved onto `surface-ink` (currently a fourth, bluer dark).
- One eyebrow style; three button roles; tags from blue to ink.

**Gates — A, B, C.** No experiment; see the banner above.

- **A (qualitative, before merge):** full-page screenshots of all five templates
  at 1440×900 and 390×844, reviewed not just captured. Both `bin/test` and
  `bin/dtest` legs green. ≥20 Clarity sessions read after ship, watching for
  anything that now reads as un-clickable — a recolour's characteristic failure
  is a link that no longer looks like a link.
- **B (guardrails, 28/28):** GSC average position on the top 20 URLs (prefix
  property), Bing+DDG sessions, LCP. Thresholds in the PR description before
  merge.
- **C (reversibility):** single PR, revert restores the previous palette whole.

The case for 1a is coherence and maintainability (ADR-0003), not a lift. No
performance claim may be attached to it.

## Phase 1b — spatial chrome

**One PR. Layout moves everywhere. Full baseline re-record, both platforms.**

- The ~200px dead fold above every H1 removed.
- Nav 7 → 5 items (Use Cases folds into Work; Careers to the footer); header CTA
  demoted to secondary so the in-page primary stays loudest.
- 4px space scale adopted; section rhythm normalised to two alternating light
  surfaces with one dark band.

**Gates — A, B, C.** This is the phase most likely to break something a visitor
notices, and the one with the least measurement behind it. Weight Gate A
accordingly.

- **A first, and heavily:** ≥20 Clarity sessions on the new chrome plus the
  rage-/dead-click report. A nav people cannot find shows up in recordings
  within days — long before it could show up in any metric at this traffic.
  Screenshots of all five templates, desktop and mobile, reviewed on the branch.
- **B (guardrails, 28/28):** GSC average position and impressions on the top 20
  URLs (prefix property), Bing+DDG sessions as the human proxy, LCP. Thresholds
  written into the PR **before** merge. Note the folded-away nav items: if
  `/use-cases` or `/careers` lose impressions, that is this change.
- **C:** revert the PR.

**Rollback:** revert the PR. 1a stays; the site is recoloured but spatially as
before, which is a coherent state to sit in indefinitely.

### The blog engagement read (informational, no longer gating)

The whole point of blog-first. Baseline recorded 2026-08-20 (Clarity,
bot-filtered): blog pages **25.2% avg scroll depth, 26.3s avg engagement,
219 sessions/3d**. Protocol:

- Re-pull the same Clarity query for the 14 days before ship (in rolling 3-day
  windows — the API caps a query at 3 days) and record it here as the firm
  "before".
- Ship 2.1 + 2.2, then read the same windows for 28 days after.
- **Moving on to the homepage (2.4) requires this read to be written up here
  first** — better, flat, or worse, with the numbers. A flat result does not
  block (the coherence case stands per ADR-0003), but an unwritten result does.
- Watch Clarity recordings of ≥20 post sessions in week one after ship — the
  qualitative gate stays primary at this traffic.

### 2.4 (homepage) carries an extra, blocking gate

The homepage cut removes the twelve service tiles and the framework logo grid.
Both carry keywords, and the site has just been through a GSC re-baseline and a
fractional-CTO cluster cannibalisation. **Before any section is removed**, pull
GSC query and page data for `/` and keep whatever earns impressions —
collapsed below the FAQ, not deleted. A conversion gain paid for in rankings is
a loss, and the pre/post read must show both numbers side by side.

### 2.2 note

`blog-single` shares `pages/blog-single.css` with `course-single`. Changing it
moves the course page too; sequence 2.3 immediately after, or accept the
coupling and screenshot both.

### Phase 0 under blog-first

0.2 (record-baselines wrapper) and 0.3 (coverage) still block — the blog
bundles have screenshot baselines on both platforms. From 0.1, only the pieces
the engagement read needs must land before 2.1: scroll-depth milestones on the
blog templates and CTA clicks with a `location` parameter. `generate_lead` and
un-marking `page_view` remain P0 but do not block the blog phases. 0.4's
denominator now includes the Clarity blog baseline above. **Light-vs-dark (open
question 0) still blocks nothing here** — the blog prototype's chrome is light,
but the cover art stays dark either way, and the blog page bodies are the least
palette-sensitive surface: if Paul later picks dark chrome, the blog body swap
rides Phase 1a like every other bundle.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Shipping six changes with no causal evidence | **certain** | accepted in ADR-0004; Gate A + reversibility are the substitute, and no lift may be claimed |
| Bot share shifts and silently moves Gate B's baselines | medium | re-read the engagement-rate tell (`.okf/workflows/analytics-access.md`) before trusting any before/after |
| `--color-primary` deletion misses a rendered consumer | medium | rendered-output check, not source grep; five-template screenshot review |
| Homepage cut costs rankings | medium | Gate 2.1 GSC check; keep, don't delete |
| Baseline re-record churn stalls the rollout | high without 0.2 | 0.2 is a hard prerequisite |
| Phase 1b lands and reads worse | low | Gate A recordings first; revert leaves 1a standing |
| Scope creep into a rebrand | medium | ADR-0003 non-goals: typeface, cover system, PostCSS all unchanged |
