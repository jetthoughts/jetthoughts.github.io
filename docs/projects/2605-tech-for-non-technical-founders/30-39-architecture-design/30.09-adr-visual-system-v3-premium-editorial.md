# ADR: Pilot a Premium-Editorial Visual System (v3) for the Course

**ADR-ID:** 2026-07-31-001
**Date:** 2026-07-31
**Status:** Accepted (3-reviewer panel, changes incorporated; ROLLOUT stays
gated on Paul's A/B eye-test of the Phase-A pilot)
**Author:** course coordinator session, from Paul's 2026-07-31 direction

---

## Title

Pilot a premium-editorial exhibit system on Module 1 with an A/B style
gate - roll out or revert on Paul's eye-test.

## Context

Paul's assessment (2026-07-31): the course visuals feel "a little old time",
some content is unstructured big-text without media or engagement, and the
course lacks the infographic quality of world-class consulting output.

Measured state backing this:

- 81 pages, 81 SVGs, 94% body-visual coverage - but THREE visual
  generations coexist (font-family occurrences ~18 Caveat-family : 12
  Helvetica/Arial : 9 Courier; only 10/81 SVGs carry the rough filter;
  strokes drift 1-2.5px).
- Compact diagrams render body text at ~5.5-7px on a 390px phone.
- Zero SYNTHESIS visuals: no program map, no per-module summary exhibit
  (Product Compass's versioned program map is the benchmark we lack).
- Reference tier violates the project's own <=600 words-per-visual DoD.
- Landing got brand type + ruby CTAs (PR #416); lesson pages wear default
  docs chrome.

**Design-review reframe (accepted):** the diagnosed problem is a
consistency/legibility/IA failure more than a style failure - "old-time"
= low-craft. The exhibit grammar (Zelazny doctrine: action titles, one
message, basis line) is style-agnostic and will not date; the flat-vector
style is the genuinely contested bet. The pilot therefore ISOLATES the
style variable (see A/B mechanic).

**Prior decision superseded-in-part:** the hand-drawn house style,
including the 2026-07-12 "clean-sans rejected by owner on sight" note.
Paul, 2026-07-31: "about Sans - I could wrongly evaluate other stuff" - a
weak prior to re-test, not a constraint. The Sam-lens reviewer additionally
reported the hand-drawn style read as AMATEUR, not authentic-humble, from
the ICP seat ("made me wonder if the content was as unfinished as the
drawings").

## Decision drivers

- D1: raise perceived craft without breaking Sam's anti-marketing trust.
- D2: exhibit grammar over gloss - action titles, one message per exhibit,
  basis lines, structured archetypes.
- D3: consistency is the loudest premium signal; generation-mixing the
  loudest anti-signal.
- D4: never big-bang 81 SVGs on unvalidated taste; isolate variables.
- D5: zero-ops, existing pipelines, no video (30.03), canon numbers only.

## Considered options

1. **O1 - Normalize hand-drawn** (consistency + grammar + 9px floor, keep
   the style). Cheapest; the A/B gate may select it.
2. **O2 - Premium-editorial flat-vector** with the same grammar + floor.
   Stripe-Press/a16z register: paper white, #121212 ink, ruby/purple
   semantic accents, green = money only, Space Grotesk LABELS ONLY (body
   stays system-ui - full Grotesk tips generic-startup, per Sam review),
   1.5-2px uniform strokes, 4px radius, no rough filter.
3. **O3 - Consulting-slick pastiche.** Rejected: breaks Sam trust, violates
   the no-decorative-visuals rule.

## Decision

Run a THREE-PHASE program. The style choice (O1 vs O2) is decided by an A/B
eye-test inside Phase A - not assumed.

**Phase A - spec + A/B pilot (start now; content-scoped, safe during the
Aug 1-14 campaign window):**
1. Write the v3 exhibit spec into house-visual-spec.md with ALL components
   the design review demanded: grid/column system, spacing scale, connector
   spec (weight, arrowheads, orthogonal routing, label placement), data-viz
   rules (chart-vs-diagram trigger, bar/line proportions, axis treatment),
   aspect-ratio standards, and the full 5-rung type scale
   (title/subtitle/label/annotation/basis) with the >=9px @390px floor.
2. Render ONE M1 exhibit BOTH ways - hand-drawn-normalized (O1) and
   flat-vector (O2) - both carrying the new grammar and floor. This pair is
   the style gate.
3. Redesign the remaining 4 M1 lesson SVGs in the O2 style (same
   filenames, in-place) WITH rewritten alt texts - an alt rewrite is a body
   edit and triggers the full visual gate, no content-only skip.
4. Eye-test doc for Paul: the A/B pair + 3 before/after screenshot pairs.
   PAUL'S CALL: O2 rollout / O1 normalization / mix. Recorded here.

**Phase B - lesson chrome (AFTER the Aug 14 metrics read - single.html is
the shared course template; a site-wide template change mid-campaign risks
a regression inside the measurement window):**
- NEW `themes/beaver/assets/css/pages/course-single.css` wired into
  single.html's `$cssFiles` slice. NEVER edit shared `single-post.css` /
  `blog-single.css` (they style every blog post). Concrete tokens: Space
  Grotesk headings, ruby #cc342d CTA/accent treatment, TL;DR card + callout
  styling mirroring PR #416's landing treatment. Full visual pair at PR
  prep.

**Phase C - synthesis assets (independent of the style gate):**
- The versioned program map ("v1.0 - July 2026" style stamp) - the Sam
  review ranks it the #1 commit-decision asset; the design review ranks it
  the hardest novel exhibit. Resolution: it ships EARLY (drafted alongside
  Phase A so Paul sees it in the same review pass) but is judged
  INDEPENDENTLY - iterate it regardless of which style wins; it does not
  gate, and is not gated by, the style decision.
- Per-module summary exhibits follow in whichever style won.

**Rollout (if O2 wins):** strictly module order M2 -> M5 -> reference, one
module per wave; cross-module navigation during the window is the accepted
worst-case view (named per design review). Sprint-Y normalization card
becomes the O1 fallback path; its classify-first audit runs first in EITHER
outcome (intentional-mono elements must be identified before conversion).

## Non-goals

- No video/animation/new dependencies; no dark-mode course pages; no
  obsidian mid-page; no blog/cover redesign; no invented statistics.
- No "LUX / world-class / top-level" language in any reader-visible copy
  (Sam review: founder-hype is a trust smell; it is a quality bar, not
  copy).

## Implementation plan (agent-ready specifics)

- **Redesign-in-place set (5):** the single existing SVG in each of
  form-your-founding-hypothesis-90-minute-sprint, smoke-test-build-page,
  smoke-test-wire-tracking, smoke-test-landing-page-7-day-demand-test,
  price-hypothesis-on-smoke-test-page. Same filename; alt text rewritten to
  the new exhibit's message; full visual gate per commit (bin/qtest
  --changed; pair at PR prep).
- **Net-new set (Phase A: 1 A/B exemplar pair rendered to a comparison doc,
  not committed to lessons; Phase C: program map in
  how-this-course-works/ + 5 module summaries):** new filenames, new
  embeds = body edits = full gate. Which lesson gets any additional
  exhibit is decided by the words-per-visual DoD, not invention.
- **CSS mechanic (Phase B):** create course-single.css; wire in
  single.html; zero edits to shared blog CSS files.
- **Estimate honesty (feasibility review):** this is 2-3 sprints total,
  phased as above - NOT one sprint. Phase A alone is one sprint.

## Verification

- [ ] v3 spec contains all 6 demanded components + type scale + floor
- [ ] A/B pair exists; both variants pass the grammar checklist (action
      title, one message, basis line) and the measured >=9px @390px floor
- [ ] 5 redesigned M1 SVGs pass grammar checklist; alts rewritten to match
      each new exhibit (checked per file)
- [ ] Phase B: chrome tokens pass/fail against the concrete list (Space

      baseline (secondary signal)

## Consequences

- Up to four visual generations coexist during rollout; mitigated by
  module-order rollout; cross-module nav is the accepted worst case.
- Sprint-Y card becomes conditional (O1 fallback path).
- house-visual-spec.md gains the grammar + floor sections in EITHER
  outcome - they are portable fixes.
- Phase B waits for the campaign window to close (post-Aug-14).

## STYLE-CALL GATE (W3, 2026-08-01) — PENDING PAUL'S DECISION

The A/B exemplar is produced (lesson 1.4 signal exhibit rendered both ways,
same message, only style differs): `40-49-review/40.30-exemplar-1.4-O1.svg`
(hand-drawn-normalized) vs `40.30-exemplar-1.4-O2.svg` (flat-vector),
side-by-side `40.30-exemplar-ab-sidebyside.png`, scored in
`40.30-exemplar-ab-comparison.md`.

**Both pass the ≥9px@390px legibility floor** (O1 10.83px, O2 9.21px,
measured in-browser with real webfonts) — neither is invalid; the choice is
pure taste + strategy. Rubric (no winner declared): O2 wins perceived craft
(3→5) and cross-SVG consistency (3→5) — the two things Paul's original
"old-time / lacks infographic quality" note named; O1 wins brand-continuity
with the existing handwritten house rule (5→2) and cost-to-adopt (5→2).
Sam-trust is a true wash (3/3, amateur-risk vs generic-startup-risk).

**Context that raises the stakes (Sprint-Y audit 40.31):** 4 of 5 current M1
SVGs FAIL the mobile floor today (the archetype signal SVG worst, 5.7-8.1px)
— so T5 fixes a live readability defect regardless of which style wins.

**DECISION (Paul 2026-08-01): O2 flat-vector.** All M1 exhibits adopt the
flat-vector style (Space Grotesk titles / JetBrains Mono labels / white card /
geometric, 4px radius, basis 17px). Rationale: O2 directly answers Paul's
original "old-time / lacks infographic quality" note, scales consistently
across all 81 SVGs, and the handwritten house rule it breaks was already
flagged for re-test by the ADR reviewers. T5 UNBLOCKED: redesign 1.1/1.2/1.3/
1.5 + finalize 1.4 into the lesson, all O2, honoring the Sprint-Y keep-as-is
list (40.31). The 4-of-5 mobile-floor failures get fixed in the same pass.
