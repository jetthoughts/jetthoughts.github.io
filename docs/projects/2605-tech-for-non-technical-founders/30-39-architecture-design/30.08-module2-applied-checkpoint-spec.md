# 30.08 - Module 2 Applied Checkpoint: "Score this practice interview"

**Date**: 2026-07-31
**Status**: SPEC - Wave F item 1 (Phase 2, un-gated by Paul 2026-07-31)
**Owner**: coordinator (flagged riskiest Wave F item - not delegated)

## What it is

One applied checkpoint at the end of Module 2, framed as practice, never as
a quiz or grade (per the 2026-07-30 synthesis: pedagogy wanted testing
effect, corpus warned novices can't self-diagnose from MCQs, Sam said
"feels like more grading" - the compromise is scoring SOMEONE ELSE'S work).

The reader reads a short fictional practice interview (a founder
interviewing a prospect about a scheduling problem, 6 numbered interviewer
questions) and judges each question against the Module 2 rules they just
learned (past behavior vs hypothetical, specifics vs generalities, no
pitching). Each question carries an instant-feedback reveal with the
verdict + WHY, quoting the course's own rule.

## Zero-ops implementation (decided - KISS ladder)

- Pure HTML `<details>`/`<summary>` reveals in the lesson markdown - the
  course already uses details toggles, Hugo renders unsafe HTML, NO theme
  change, NO JS, works printed and offline.
- Each summary carries `data-course-event="checkpoint-reveal"` +
  `data-course-label="q1..q6"` - the EXISTING course-analytics delegation
  fires GA4 events, giving per-question engagement measurement for free.
  (Verify delegation covers course lesson bodies before shipping.)
- Rejected: radio-button JS widget (new theme component, both visual
  suites, zero additional pedagogy value).

## Placement

Lesson 2.5 (Synthesis / decision gate) - AFTER the synthesis content,
BEFORE the BUILD/PIVOT/KILL gate block, as "Pressure-test your read"
so the reader calibrates on a neutral transcript before scoring their own
interviews. Must not disturb the gate's canonical numbers (BUILD 7+ /
PIVOT 4-6 / KILL <4 - ratchet-protected).

## Content rules

- Transcript is explicitly fictional and neutral-domain (scheduling tool -
  not any domain used by Mia or other course examples, to avoid anecdote
  collision).
- 6 interviewer questions: 3 violations (one hypothetical-future, one
  pitch-in-disguise, one compliment-fishing), 3 clean (past-behavior,
  specifics, cost-of-problem). Order shuffled, not alternating.
- Every verdict quotes/links the rule's home lesson (2.1 Mom Test script,
  2.2 personas, 2.4 sequence) - no new doctrine introduced.
- Sam-voice; no scores, no percentages, no pass/fail language. Closing line
  points back to the reader's own transcripts, not to a grade.

## Validity gate before ship

Per-item check (assessment-validity): (a) answerable using ONLY what
Modules 1-2 teach; (b) exactly one defensible verdict per item; (c) the
distractor questions are plausibly attractive (real founder mistakes, not
strawmen). Any item failing any check gets rewritten or cut - 4 good items
beat 6 weak ones.

## Measurement

GA4 `course_checkpoint_reveal` events (per-question labels) ride the
existing funnel. Success signal to look for later: reveal usage on q1-q6 +
no drop in 2.5 -> 3.1 continuation. If reveals go unused after real traffic
arrives (Wave G), the checkpoint is a removal candidate per the board's
standing effectiveness rule.
