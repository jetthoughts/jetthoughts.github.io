# 10.06 — Course Media Design Recommendations

**Date:** 2026-07-26
**Status:** Research-informed recommendations (not yet adopted)
**Project:** 2605-tech-for-non-technical-founders
**Audience:** Sam — idea-stage non-technical founder, first-time builder, low time availability

**Based on:**
- Enforced media design guidelines: `30-39-architecture-design/30.07-media-design-guidelines.md`
- Existing course design system (`.okf/design/house-visual-spec.md`, `.okf/design/course-typography.md`, `.okf/design/mermaid-theme.md`)
- Course format requirements (`30.03`)
- Current course spine (`20.01`, `20.09`) — 5 modules + Going Further set
- Existing visual assets: hand-drawn SVGs, Mermaid diagrams, cover-image pipeline

---

## Executive summary

The JT course currently ships **text-only micro-lessons** with occasional
hand-drawn SVGs and Mermaid diagrams — per the 30.03 spec's "text-only with
small graphs and images. No video" directive. This is correct for a
text-first, mobile-optimized course aimed at Sam.

**These recommendations do NOT propose adding video or slide decks.**
They propose **layering the media-mix thinking from the external guidelines
onto the existing text+SVG+Mermaid format**, adding specific templates,
canvases, checklists, and before/after pairs where each module's current
SVG or diagram can be strengthened.

|---|---|---|

| **Mermaid diagrams** | Used per `mermaid-theme.md`. Flowcharts, decision trees. | Keep. Replace multi-node (>5) flowcharts with simpler 3-4 node versions. Add data-flow diagrams for M4 (stack wiring). |
| **Templates/Canvases** | 6 Founder OS artifacts exist; PDF pipeline in `bin/generate-template-pdfs`. | Add: Module 1 scenario sheet, Module 2 interview scorecard, Module 5 channel-fit canvas. |
| **Checklists** | Ownership checklist exists (M4). | Add: per-module before/after checklists (M1 hypothesis sanity check, M2 interview prep checklist, M3 review gate checklist, M5 pre-launch checklist). |
| **Data visuals (charts)** | Minimal — mostly Mermaid. | Add plain-language KPI caption format for M2 (conversion data), M5 (PMF score). |
| **Slide decks** | None. Course is web-native. | Not needed — the web page IS the slide. Each micro-lesson follows the Problem → Visual → Insight → Action pattern natively. |
| **Videos** | None per 30.03 spec. | Not recommended for v1. Consider as a future companion channel (Module 0 overview video). |

(invoice-loop-style for smoke-test flow).

**Recommended additions:**

| Asset | Format | Purpose | Placement |

|---|---|---|---|

for deployment plumbing.

## 4. Application of the external guidelines' format specs to JT course

The external media design doc (§5) specifies formats by type. Below is how
each applies (or does not apply) to the JT text-based course.

### Slides (§5.1) — NOT APPLICABLE

The course is web-native Hugo pages, not slide decks. The **Problem → Visual
→ Insight → Action** slide layout pattern maps naturally to the 8-part
micro-lesson template:
- Hook (Problem)
- Minimal concept block + Visual (Visual)
- Do This Now + Success check (Insight)
- Closure block (Action)

No slide creation needed.

### Videos (§5.2) — FUTURE CONSIDERATION

The external spec recommends 3-7 min explainer videos. The 30.03 course
format spec explicitly bans video ("Text-only with small graphs and images.
No video.") for Sam's ICP. This is correct — video increases friction
(requires headphones, cannot scan, hard to reference). Revisit only if
analytics show Sam stalls at a specific concept, and even then prefer an
animated SVG or interactive diagram over a talking-head video.

**Exception:** A single 2-minute "How this course works" overview animation
for Module 0 (course map) could increase start rate. This is P4 priority.

### Charts and data media (§5.3) — APPLICABLE

The external spec's rules align with what the course already does:
- Show only necessary metrics (M2: conversion rate, M5: PMF score)
- Plain-language captions — adopt as a style-guide rule for every chart
- No 3D charts or complex visualizations — already followed

**New rule to add to style guide:** Every KPI or data point in a lesson
should have a parenthetical or callout that answers "What do I do with this
number?" Example: "If your click-to-payment-intent is below 5%, go back to
Lesson 1.1 and sharpen the hypothesis before spending on more traffic."

### Templates and canvases (§5.4) — APPLICABLE

The external spec requirements match existing JT practice:
- Single-page with clear sections ✓ (ownership checklist)
- Example-filled + blank versions ✓ (PDF pipeline)
- Language consistent with course voice ✓

**Gap:** The course currently has 6 Founder OS artifacts. The external
guidelines recommend per-module templates and canvases. The scorecard,
channel-fit canvas, and checklists above add the missing coverage.

## 5. Interaction pattern mapping

The external guidelines (§4) recommend per-module interaction patterns.
Below is how they map to the JT 8-part lesson template.

| External pattern | JT template equivalent | Current status |
|---|---|---|
| **1-2 short questions** using the media | Micro-Reflection (§2.8) | ✅ Already exists in every lesson |
| **1 small task:** fill a canvas, run a calculation, rewrite an email | Do This Now (§2.5) | ✅ Already exists (3-7 imperative steps) |
| **1 reflection:** "Where could you apply this?" | Micro-Reflection (§2.8) question | ✅ Exists — verify the question prompts real-work application, not just recall |
| **Scenario/problem opener** (module start) | Hook (§2.1) | ✅ Exists |
| **Chart/diagram to make concept tangible** | Visual Micro-Aid (§2.4) | ⚠️ Exists but inconsistently — a few lessons skip the visual (per 40.08 gap report) |
| **Use template/canvas to apply** | Do This Now (§2.5) | ⚠️ Not every lesson that introduces a template has a fillable step using it |
| **Close with real-life application checklist** | Closure Block (§2.9) + checklist asset | ⚠️ Checklists exist only for M4 ownership. Every module should end with a checklist. |

**Verification action:** Run a targeted audit: for each lesson that
introduces a template/canvas/checklist, confirm the Do This Now section has
a step that explicitly invokes it ("Open your [template]. Fill section A
with your hypothesis from Lesson 1.1.").
