# Editorial-system consolidation review - 2026-08-28

Paul supplied a full thoughtbot-style editorial blueprint (corpus extraction →
voiceprint → topic scoring → evidence packs → staged drafting → delivery
manifests → 30/90/180 refresh) and asked to consolidate our blog system with
it. This is the verdict, mapped item by item, so nobody re-proposes the
rejected machinery from intuition next quarter.

**Headline: the repo already runs a harder version of most of it.** The
proposal describes a system designed from first principles; ours is the same
shape hardened by documented failures (search-demand-driven topic selection
falsified twice, regex slop gates deleted by Paul, panel-caught fabrications).
Where the proposal was ahead, we adopted - four surgical skill edits, no new
machinery. A two-lens review panel (KISS/deletion + gap-hunter, both
PASS-with-edits) shaped the final form; the gap-hunter's dissent supplied the
fourth adoption.

## Adopted (2026-08-28)

| Delta | Landed in |
|---|---|
| Falsifiable-thesis test at the outline gate: thesis a reader could disagree with, named holder of the flawed default, steelmanned counterargument, boundary conditions, one-line non-scope | `blog-next` Stage C |
| Evidence-pack excerpt + wording-strength discipline: every claim carries the exact supporting excerpt, the source's own caveat, and the verb the excerpt licenses (demonstrates / reports / suggests / may); the claim lens diffs draft sentences against excerpts and traces every footer source to the sentence that spends it | `blog-next` Stage B output spec; `blog-write` panel lens 4 |
| Five-search-results rejection clause: a post writable entirely from the first five search results has no original contribution | `blog-next` Stage A1 |
| Code-rot REPAIR trigger (the blueprint's 180-day re-verification leg): top-impressions posts carrying runnable commands or pinned versions get re-run in a clean shell; 51 own posts carried runnable fences with no re-check path as of 2026-08-28 | `blog-operator` step 1 |

Why these four: each targets a documented defect class no existing gate
covered. The thesis test targets "polished summary with no point of view"
(voice guide demands opinions but no gate demanded one before prose existed).
The excerpt + verb discipline is the mechanism for "a source's own words
checked, its attribution not" and "cited but never spent" (2026-08-22, two of
three posts). The five-results clause is the cheap form of "somebody else's
post". The code-rot trigger covers the one refresh element nothing here
watched - GSC never reports a snippet that stopped running.

## Already covered - no change

| Proposal | Our equivalent (stronger, with evidence) |
|---|---|
| Topic discovery + weighted scoring formula | `blog-next` Stage A: signals generate, search VETOES. Search-demand-driven selection was falsified twice here - both Aug 2026 audits killed the queue's own lead row (~0.69 named non-brand clicks/day; ICP absent from query data) - so a demand-weighted formula would automate the falsified input |
| Four per-family style guides | Voice guide §1b channel registers + §7 content streams + reference-samples cadence anchors |
| Quality rubric with thresholds | 3-critic panel (≥8/10) + cold-eyes 10-check gate + zero-tolerance fabrication canon |
| Stage separation (researchers don't draft, drafters don't invent evidence) | author ≠ verifier on every stage; `blog-next` never writes, `blog-write` never re-researches |
| Code validation checklist | "run every command you publish in a clean shell" + tech critic verifies every copyable line + version-specificity rules |
| CMS delivery manifest, JSON-LD | Hugo templates own it (`article-schema.html`, `enhanced-meta-tags.html`) - a manifest would duplicate the build |
| 30/90-day refresh legs (indexation, CTR, query gaps, internal links) | `blog-operator` REPAIR > UPGRADE > WRITE ordering, GSC-driven, runs on every invocation - continuous beats scheduled at our volume. The 180-day code-re-verification leg was NOT covered by anything; adopted above as the code-rot REPAIR trigger |

## Rejected

| Proposal | Why |
|---|---|
| Corpus factory (crawl thoughtbot, raw/normalized/derived JSONL, structural/lexical feature extraction) | Weeks of tooling to approximate what the competitor-standard lens gets by FETCHING two current posts live. Contradicts "slop is found by cold eyes, never by a score or a grep" (Paul 2026-08-22) - lexical features are exactly the regex that got `bin/check-post-voice` deleted |
| 40-80 annotated gold set | `blog-writer-reference-samples.md` + live fetches are the working exemplar set. Grow it one sample at a time when a post reveals a missing shape, not as a batch project |
| Snippet manifests (YAML per code block) | The clean-shell rule + tech critic already enforce the substance; the manifest is bureaucracy around it |
| Retrieval-based drafting infrastructure | The drafting packet already exists: voice guide + cadence anchor + topic row + digest. Embedding retrieval adds a system to maintain, not quality |
| Distribution package generation | LinkedIn is deliberately its own lane (drafts-only, own pipeline); coupling it to blog publishing crosses a boundary Paul set |

Boundary note: the proposal's "don't publish as thoughtbot" section doesn't
apply - we model the editorial standard, we publish as JetThoughts, and voice
guide §6b already frames thoughtbot as a measured competitor standard, not a
disguise.
