## The one-line diagnosis

This repo's AI-ops failure mode is not missing rules — it is **things that
report or imply activity while doing nothing**: a mandated memory store nobody
reads (1 read across 591 post-mandate entries), a course validator whose only
caller is an uninstalled git hook while a unit test asserts the hook's text
and passes, learning hooks that no-opped for months behind `|| true`, a
"BLOCKED" message that doesn't block, an ENFORCED rule naming an agent
(`okf-maintainer`) that has never existed, a fallback memory chain that is
quota-dead (mem0, until 2026-09-01) or answers from another codebase
(memoria → Elital), and BLOCKING pipeline gates whose skills are deliberately
not vendored so container sessions skip them silently.

   PROJECT entry (CLAUDE.md hardcodes `mcp__ruflo__*`), drop the plugin's.

   pointers that rotted; delete BASE_HANDBOOK and repoint agents.
5. **Nine memory systems, one wired** (lens 3, direct SQL). Only auto-memory

   namespace is a 5th copy layer with no binding test. Its dissent (adopted):
   one read may mean nobody WIRED it, not nobody needs it — wire one
   retrieval call into `bin/agent-bootstrap`, measure reads 30 days, THEN
   decide the architecture. MEMORY.md has a scaling ceiling ruflo doesn't.
6. **Contradiction webs from unswept corrections** (lens 1). The docs-PR CI
   rule exists in three states (CLAUDE.md 2026-08-22 "don't wait for CI" vs
   AGENTS.md "+ CI" vs delivery-prompt self-contradicting at :27/:54) —
   verified: NO workflow fires on docs-only PRs, so "+ CI" names a gate with
   no firing path. The same-day correction updated one file and missed two —
   the exact "sweeping the instruction layer" failure CLAUDE.md warns about.
